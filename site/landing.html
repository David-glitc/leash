How it works

One rule. Three keys.

An AI agent that pays or trades holds a key, and today that key is classical. A limit means nothing if the same key can raise it. Leash splits the power so no single key can.

The agent’s key

secp256k1

Can spend and act inside the mandate: caps, an allowlist, an expiry, routes with rate floors.

Cannot raise a cap, add a recipient or extend the expiry.

The owner’s classical key

secp256k1

Can freeze the guard, instantly.

Cannot start or loosen anything. If it leaks, or a quantum computer breaks it, an attacker can pause the agent and nothing more.

The owner’s post-quantum key

ML-DSA-87

Can sign every mandate. QoreChain’s pqcVerify precompile checks the signature on chain against the key the owner registered.

Never held by the agent, and never used to spend.

LeashGuarda contract on QoreChain that holds the funds and enforces the mandate
  • per-action and daily caps
  • recipient allowlist
  • expiry
  • owner-signed routes
  • rate floors, measured on what it received
  • freeze

What it does

Agents pay and act. The chain keeps count.

Version 1 lets an agent pay. Version 2 lets it swap, wrap and use vaults. The rule never changes: the agent never gets to loosen its own leash.

Honest limits

What this is not.

  • Testnet only. pqcVerify is not active on mainnet yet.
  • Unaudited. Small and heavily tested, with an audit package ready, but not independently reviewed.
  • Our own test router. QoreSwap’s router address is not published, so the testnet run uses test contracts. Blocked rows of the testnet drill are simulated calls.
  • No price oracle. A rate floor is the owner’s own number.
  • No bridging. No bridge route is live on QoreChain.
